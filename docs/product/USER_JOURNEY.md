# Book Maker User Journey

## 1. Journey Goal

This journey describes how a general user moves from casually writing short pieces to feeling that they are building a book draft.

The core emotional shift is:

"I should write a book someday"

to

"I am already writing material for my book"

## 2. Persona Summary

The primary user:

- used to write short texts on Instagram or similar platforms
- enjoys writing personal but relatable thoughts
- does not want the pressure of formal long-form writing
- wants their writing to be saved, searchable, and meaningful over time
- feels frustrated that past writing is hard to organize into a larger narrative

## 3. Journey Stages

### Stage 1. Spark

The user experiences a moment worth writing down.

Examples:

- a late-night reflection
- a memory about someone
- a feeling after a conversation
- a short thought that feels like it could become something more

User goal:

- capture the moment before it disappears

Pain points:

- writing tools can feel too heavy
- if the writing is posted to SNS, it becomes hard to manage later

Product opportunity:

- offer a fast, low-pressure writing entry point

### Stage 2. Quick Capture

The user writes a short entry.

User goal:

- save the thought quickly without needing to structure it too much

Expected product behavior:

- open directly into writing
- allow title to be optional
- save the date automatically
- make completion feel immediate

Emotional state:

- relieved
- lightly accomplished

Product opportunity:

- make short writing feel valid and valuable

### Stage 3. Accumulation

The user keeps adding more entries over time.

User goal:

- continue writing without feeling forced into a formal project

Pain points:

- if entries are only shown as an endless list, they may feel disposable
- the user may not notice progress

Expected product behavior:

- show entries clearly in one archive
- make accumulation visible
- help the user feel that each short text matters

Emotional state:

- curiosity
- quiet ownership

Product opportunity:

- reinforce the feeling that these are not random notes, but material

### Stage 4. Rediscovery

The user revisits older entries.

User goal:

- find past writing
- reconnect with themes, moods, people, and periods in their life

Pain points:

- on SNS, past writing is difficult to retrieve and reorganize
- the user may not remember when a piece was written

Expected product behavior:

- provide chronological browsing
- provide previews
- support simple search or filtering

Emotional state:

- surprise
- nostalgia
- recognition of personal patterns

Product opportunity:

- turn passive storage into meaningful rediscovery

### Stage 5. Grouping

The user begins selecting several entries that seem connected.

User goal:

- test whether these pieces can belong to the same story or theme

Pain points:

- the user may not know how to begin "making a book"
- a full editing workflow can feel intimidating

Expected product behavior:

- let the user select entries simply
- let them create a named draft
- let them reorder entries without complexity

Emotional state:

- cautious excitement
- creative possibility

Product opportunity:

- transform scattered entries into a visible narrative structure

### Stage 6. Book Draft Experience

The user sees selected entries presented as a continuous reading experience.

User goal:

- understand whether their writing can feel like a book

Expected product behavior:

- show a clean draft view
- make the transition from "entries" to "draft" obvious
- help the user imagine continuing the work

Emotional state:

- pride
- motivation
- momentum

Product opportunity:

- create the moment where the product proves its value

## 4. Core User Needs

Across the journey, the user needs:

- a low-friction way to write
- confidence that short writing is enough to begin
- a reliable archive of past writing
- a way to see connection between separate entries
- a visible path from writing fragments to book draft

## 5. Core Product Implications

This journey suggests the product should prioritize:

- fast capture over complex editing
- archive quality over social engagement
- emotional motivation over productivity language
- draft formation over publishing workflows

## 6. MVP Design Questions

The next planning stage should answer:

1. What is the fastest possible way to create a new entry?
2. How should the archive show progress without feeling cluttered?
3. What is the minimum interaction needed to group entries into a draft?
4. What should the draft preview look like to feel book-like, not just list-like?
